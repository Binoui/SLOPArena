# AI-assisted 3D production workflows for SlopArena

Research date: 2026-10-15. Scope: signature stage creation and existing-stage polish, with optional model/VFX improvements. This is a source review and proposed transfer of practices; no tools were installed, external code executed, paid generations submitted, or Unity/Blender sessions operated.

GitHub's commits API resolved these snapshots: [gamedev-skills `0a70cfc`](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/commit/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd), committed 2026-10-09; [OhMyGame `2cec05e`](https://github.com/WhiteTowerAI/ohmygame/commit/2cec05e4af5c83d341a02df3462088475685c772), committed 2026-10-14. External links below pin those revisions. Findings distinguish written workflows from implemented code; provider tests were inspected, not run.

## 1. Gamedev-skills: useful production discipline

The strongest contribution is `create-game-assets`: inspect existing art; fix camera, scale and technical constraints; describe a visual system; approve one representative target; produce related assets from that reference; normalize through ordinary DCC/image tools; import and inspect in context; retain provenance. Its [art-direction reference](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/disciplines/create-game-assets/references/art-direction.md) makes shape, value bands, palette roles, edges, materials, lighting, detail density and motion explicit. It evaluates thumbnail/game scale, working scale and the surrounding game composition. This gives concrete language for why individually attractive props may weaken a stage.

The [brief template](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/disciplines/create-game-assets/assets/art-direction-brief.md) and [manifest template](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/disciplines/create-game-assets/assets/asset-manifest.json) are reusable patterns. A family can share palette, material response, proportion, viewing distance and reference images while varying one asset-specific feature. The [provenance guidance](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/disciplines/create-game-assets/references/provenance.md) adds tool/model, prompt or source record, acquisition date, terms, attribution, derivatives and approval. For SlopArena, add missing production records to existing stage/package ownership rather than creating another runtime catalog.

The [3D pipeline](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/disciplines/create-game-assets/references/three-d-pipeline.md) is a checklist, not an exporter or mesh generator. It explicitly calls for Blender cleanup, topology/normals/UV/rig checks, meaningful pivots, simple collision proxies, appropriate resource reuse, and actual engine validation. Its general GLB preference is conditional on target support; it supplies no reason to replace SlopArena's established FBX import path.

Two bundled scripts are actual small implementation candidates:

| Script | Implemented behavior | Limitation found by reading code |
| --- | --- | --- |
| [`asset_report.py`](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/disciplines/create-game-assets/scripts/asset_report.py) | Dimensions, file size, color count, alpha statistics and content bounds; optional constraints; JSON and exit status. | `--require-alpha` checks channel presence, so opaque RGBA passes. Exactly `max_colors + 1` can also pass: enumeration allows that count, while failure only checks overflow represented as a string. Correct these edges before relying on them. |
| [`build_preview_sheet.py`](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/disciplines/create-game-assets/scripts/build_preview_sheet.py) | Stable sorted input, checkerboard, labels, nearest-neighbor fitting and contact-sheet output. | Raster presentation only; it neither normalizes production meshes nor establishes shader parity. Nearest-neighbor is appropriate for pixel art, not every 3D texture review. |

These require Pillow. They are optional helpers for atlases, icon/effect families and review sheets, not a necessary new dependency. The [raster reference](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/disciplines/create-game-assets/references/raster-pipeline.md) also contributes useful 3×3 texture-repeat checks and low-contrast backgrounds behind gameplay.

[`procedural-gen`](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/0a70cfc64672d512c5b5b6006b5dcb5cf90dbdbd/skills/disciplines/procedural-gen/SKILL.md) contains instructions and illustrative algorithms: owned seeded RNG, data generation separated from drawing, bounded attempts and reachability checks. It is not a ready 3D stage tool. Transfer reproducibility and validation; do not introduce dungeon/noise algorithms into a deliberately composed fighter arena merely because they are available.

## 2. OhMyGame: resolve the place, then inspect its realization

The [`threejs-world` expansion guide](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/plugins/threejs-world/skills/threejs-world/references/world-expansion.md) inventories regions, routes and hero subjects, then resolves each through placement, connected construction, surrounding activity, materials, close detail, atmosphere, viewing angles and acceptance views. It connects world composition to recognizable structures and local details, with varied density and deliberate negative space. Its completeness gate asks whether implementation would still need to invent major design decisions. These are written production instructions, not an executable world builder.

The [worked station example](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/plugins/threejs-world/skills/threejs-world/references/expansion-example.txt) demonstrates causal specificity: roof drainage, utility connections, wear around activities, vegetation at boundaries, and foreground/midground/background composition. The reusable idea is coherent relationships. Its long shopping streets, abundant small props and walking-camera detail should not become a SlopArena content quota. Spend detail where the combat camera can see it; keep recovery corridors and fighter silhouettes clear.

The [world contract](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/plugins/threejs-world/skills/threejs-world/references/world-contract.md) calls for named editable regions and landmarks and rejects counting objects as proof of finish. The [validation guide](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/plugins/threejs-world/skills/threejs-world/references/validation.md) supplies the valuable loop: build/run, operate real controls, capture required views, actually inspect pixels, record specific defects, correct them, and recapture affected views. It distinguishes technical results, visual judgment and human approval. Repeating screenshots without new findings adds no evidence.

The [presentation guide](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/plugins/threejs-world/skills/threejs-world/references/presentation.md) is for a browser world showcase: title, location copy, view navigation, entry action, responsive panels. Transfer focal hierarchy and accurate review-view names to production evidence. A showcase overlay, mobile page layout or explorable museum mode would add unrelated product work.

## 3. OhMyGame code: selective lessons, explicit limits

The newer [Game Studio](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/plugins/game-studio/skills/game-studio/SKILL.md), [Foundations](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/plugins/game-studio/skills/game-foundations/SKILL.md) and [QA](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/plugins/game-studio/skills/game-qa/SKILL.md) workflows explicitly preserve the selected engine, distinguish simulation from presentation, and direct native verification through existing engine tools. This supports keeping Unity/Blender. General engine support in prose must be distinguished from these implemented capabilities:

- **Asset lineage:** [`canvas-assets.ts`](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/src/daemon/canvas-assets.ts) materializes Library assets into a project manifest, preserves `libraryAssetId`, and compares SHA-256 file digests when returning edited assets to the Library. Transfer source → derivative → imported artifact → runtime-use traceability. Canvas descriptions/prompts are not verified visual observations, as its [file-contract documentation](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/docs/canvas-agent.md) explicitly states.
- **GLB checks and axis handling:** [`model3d-inspect.ts`](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/src/daemon/model3d-inspect.ts) parses geometry, counts triangles and records texture/skin presence and animation names. For explicitly known +X models it adds a rotated parent for +Z, preserving local skeleton/animation coordinates. This does not infer semantic front, repair topology, validate UV quality, normalize units/pivots, or prove acceptable rigging. SlopArena already has its own verified coordinate/export conventions.
- **Provider orchestration:** [`provider-models3d.ts`](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/src/daemon/provider-models3d.ts) dispatches Meshy, Tripo and Hyper3D operations with capability checks. The [provider workflow documentation](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/docs/3d-providers.md) clearly distinguishes image/text generation, retexture, remesh and rig/animation support. Outputs are GLB; this is not a Unity importer or package cook. [`model3d-journal.ts`](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/src/daemon/model3d-journal.ts) fingerprints paid submissions, persists task credentials and refuses ambiguous resubmissions. That recovery pattern is useful if paid generation later becomes routine; importing its daemon now is disproportionate. [Tests](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/test/model3d-workflows.test.ts) use fixtures and mocked APIs, not proof of live account entitlement or output quality.
- **Runtime limits:** [`ProcessPlaytestDriver`](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/src/daemon/playtest-driver.ts) uses Web capabilities. [`playtest.ts`](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/src/shared/playtest.ts) names Unity/Godot in types, but the [runtime documentation](https://github.com/WhiteTowerAI/ohmygame/blob/2cec05e4af5c83d341a02df3462088475685c772/docs/runtime.md#runtime-adapter-boundary) confirms only Web/Chromium ships. It cannot currently replace SlopArena's gateway, native captures or gameplay replay.

## 4. Recommended transfer to the existing pipeline

The following is an inference from those sources and SlopArena's current workflow, not an external tool capability or an approved architecture change.

1. **Extend the existing stage brief.** Use [stage design](../../skills/sloparena-stage-design/SKILL.md) as owner of composition. Add concise region/hero expansion, palette/material families, observable visual targets and named acceptance views. Keep its current gameplay-shell, orbit, recovery-clearance and human-review rules. Avoid parallel `.world/` design files or a second broad skill router.
2. **Capture a fresh baseline before choosing repairs.** Use real materials, lighting, fighters and the evaluated gameplay camera. Record camera pose, viewport, quality, lighting/time and stage/source identity. Keep structural/clearance captures distinct from appearance evidence. Adapt OhMyGame's defect table to silhouette, contact/support, material hierarchy, repetition, fighter separation and false landable cues. Fix the most consequential visible issue, then compare identical views.
3. **Produce a representative family first.** Finish one landmark fragment, one supporting surface/prop family and one gameplay-scale composition before dressing every region. Use existing asset selection for missing roles. Use Blender procedural construction for repeatable architecture/surfaces, authored or sourced models where they improve identity, and generated images as concept/material inputs requiring cleanup. Preserve quieter space.
4. **Retain a reproducible production packet.** Build on the [Sanctuary example](../../tools/blender/fightguy_sanctuary/README.md) and [reuse guide](../../tools/blender/README.md). Alongside source and generated art, retain generator revision/hash, inputs, seeds, Blender version, command/options, atlas/material dependencies, export/import settings and artifact hashes. The existing [build stamp](../../tools/blender/fightguy_sanctuary/build.py) records the layout source hash; it is not a complete rebuild receipt. Provision the ignored cosmetic prefab or document its verified reconstruction.
5. **Verify appearance and cost in Unity.** Preserve [StageVertexLit](../../client/Unity/Assets/Shaders/SlopArenaStageVertexLit.shader) semantics: vertex colors, atlas/detail multiplication, alpha masks and cosmetic wind. Blender previews remain approximations. Measure actual-frame CPU/GPU cost, draw calls, material/texture memory and overdraw where available; triangle counts alone do not describe render cost. Keep cosmetic geometry separate from authoritative stage collision under [stage authoring](../../skills/sloparena-stage-authoring/SKILL.md).
6. **Prove reuse on both task types.** Sanctuary supplies a construction reference. After Hours is an existing dark-stage candidate whose [brief](../design/stages/after_hours.md) still records pending human review; a fresh baseline must establish its present defects. Then apply the same production packet to one new signature stage. Extract shared generator code only after the second use demonstrates the common part.

Optional model/VFX work can use the same family/scale/context checks: signature hero props, coherent impact shapes, bounded ambient motion and clear hit-state contrast. Keep hit results and timing in Shared; do not let cosmetic shader motion or an imported animation create gameplay behavior.
