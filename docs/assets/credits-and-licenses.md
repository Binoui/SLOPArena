# Asset source and license notes (maintainers)

The public-facing thank-you and creator links live in [CREDITS.md](../../CREDITS.md). This document tracks source evidence, attribution wording, and release checks. Update the public credits when a creator or pack is identified; keep uncertainty and packaging work here rather than in the thank-you.

The [contributor input inventory](contributor-inputs.md) records actual catalog,
scene and Resources availability. See the
[Pipeline fork proposal](../plans/2026-10-13-unity-dependency-ownership.md#pipeline-fork-and-upstream-licence)
for its upstream licence, original contribution provenance and unresolved source
publication route. Neither the fork nor vendor asset adaptations acquire MIT
rights from the root project licence.

**Cooked animation files already tracked:** `git ls-files` shows `content-cooked/{fightguy,wibou,bonk,manki}/poses.bin` in Git while the inspected source `.anim` files are ignored. The pose files are sampled from bound clips. Check whether each source pack permits publication of those derived files as well as use inside the player build; excluding raw packs from Git does not resolve that question.

For each pack or independent asset in a release, retain the creator's preferred name, original product link and version, which part of the game uses it, purchase/download evidence kept privately, and required credit or full notice. Compare this register with the **built player and server**, not only the repository. The [project MIT license](../../LICENSE) and character `package.json` metadata do not cover third-party assets. Follow the [asset conventions](../contributing/conventions.md#third-party-and-licensed-assets) for repository hygiene.
